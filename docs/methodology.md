# Methodology

This page describes exactly how Sourcly labels and ranks results. Nothing here is learned, hidden or generated by a language model: the same results and settings always give the same ranking, and every decision can be inspected in the app ("Why this rank?" and the label reasons).

## How a search works

1. **Read the query.** What you type is first checked for being a DOI, a link, an ID or a long title (see "Looking up one work"). Otherwise it is read as **concepts** (see "Writing a search"): quoted phrases and the other content words each become one concept, common words are never searched, generic words such as "understand" or "using" are not required, and each concept gets a few curated alternatives (spellings, abbreviations, close synonyms). Your text is never changed. "How we searched", collapsed under the results heading, shows the concepts, which alternatives came from the thesaurus, the words that were set aside and the exact query each source received.
2. **Search.** The concepts are written once for each source, in the syntax that source understands, and sent to every selected source at the same time, directly from your browser. There is no Sourcly server. Only four sources are on by default (see "Default sources"). Each source is asked for up to 100 results (you can choose 25, 50 or 100 in Settings); at 100, OpenAlex is asked for two pages, up to 200 works, and Crossref is only a 20-row supplement. A source that allows fewer per search simply returns fewer (Zenodo 25, Wikipedia 5). A source gets 15 seconds to answer.
3. **Show results as they arrive.** Each source's results appear the moment it answers, and the list re-sorts as more come in, so the order can change until every source has finished.
4. **Fall back, if few results match every concept.** When the strict first pass is finished and fewer than 15 merged results match every concept, up to three more passes run by themselves, each with one concept dropped, the least specific first ("Fallback passes").
5. **Normalize.** Each source's answer is converted into one common record (title, authors, year, venue, DOI, type, citation count, language, author countries, open-access status, retraction flag, subject terms, and which sources returned it).
6. **Merge duplicates.** A work that several sources returned becomes one result that lists every source that found it, once each (rules below).
7. **Label.** Each result gets two labels, from the rules below, and a language ("Language detection").
8. **Match, score and place.** Every result is checked against every concept, locally (see "Term coverage and tiers"). Each result gets a score from the factors below, using your weights. Results are ordered by how many concepts they match, then by whether neighbouring concepts are next to each other, then by score, and placed in the main list or one of three collapsed sections ("The main list and its sections"). Relevance is worked out over all the merged results together.
9. **Page.** The main list is shown 25 to a page. "Suggested terms" under the search box are taken from its top 30.

Steps 6 to 9 use only data already fetched. Changing a weight, a switch, a label, a filter, a preferred language or the page updates the list instantly without contacting any source. Your label overrides last for the current visit; they are not saved.

**Nothing is deleted.** A result is either in the main list, in a collapsed section under it (each with a count and the same cards), or hidden by a filter you set, which the page counts and lets you clear.

## Default sources

Four sources are on by default: **OpenAlex** (the backbone: a large open index of scholarly works in every field), **Crossref**, **PubMed** and **Europe PMC**. They give clean scholarly records and each can be asked in a way that matches your words. The others are one click away in Settings, each with a one-line reason:

| Source | Off by default because |
| --- | --- |
| DataCite | Anyone can deposit, so a search returns datasets and repository items with a lot of noise. |
| Zenodo | Anyone can upload, with no review: spam-like items, datasets, slides. At most 25 results. |
| DOAJ | Open-access journals only, a narrow slice that OpenAlex and Crossref already cover. |
| Wikipedia | An encyclopedia, not a source for a paper; when on, at most 5 pages. |
| Semantic Scholar | Its free shared pool is often busy and refuses requests, and a refusal cannot be read by a browser. When it is off it is not asked, and no status line for it is shown. |
| arXiv | Cannot be searched from a browser (shown as not available). |

A source that is off is never asked, and nothing is sent to it.

## Writing a search

Everything here is a fixed rule. The same text always gives the same query, and nothing is guessed. There is no language model, no embedding and no learning: a search is lexical (it matches words), not semantic (it does not know what they mean).

| You type | It means |
| --- | --- |
| `machine learning odor prediction` | Three concepts, all required: *machine learning*, *odor* and *prediction*. A space means AND. |
| `"memory consolidation"` | One concept: the words together, in that order, every word inside the quotes kept, and never given alternatives. |
| `sleep OR nap` | Either word. Never given alternatives. |
| `sleep NOT rats` | `sleep`, but not `rats`. |
| `(sleep OR nap) memory` | Parentheses group. |
| `How AI understand odor` | Two concepts, *AI* and *odor*. "How" is a common word and "understand" a generic word: neither is required. |

`AND`, `OR` and `NOT` are operators only in capitals. A hyphen between letters or digits stays inside the word (`covid-19`, `off-target`, `IL-6`), because splitting it breaks real searches: PubMed finds nothing for `covid AND 19` (checked 2026-10-14). Other punctuation splits a word (`sleep/memory` becomes `sleep memory`), and apostrophes are dropped.

### Concepts, and the three kinds of word

A search is read as a list of **concepts** (the code calls them blocks, `packages/core/src/concepts.ts`). Each concept is one thing a result must be about. Every word you type is in exactly one of three classes, decided by fixed lists:

1. **Common words** (stopwords) are **never searched**: *how, what, can, the, of, is, ...*. The list (below) is fixed and short, nothing is learned, and it is viewable in Settings. Words inside quotes are always kept, and **a word in capitals is never a common word**: `CAN bus` keeps `CAN` (the controller area network), and `can AI predict odor` drops the verb `can`.
2. **Generic words** (soft terms) are **not required**: *understand, understanding, use, using, used, work, way, make, help, new, novel, study, studies, effect, effects, impact, role, based, approach, via, toward, towards, explained, overview, method, ...*. They say how a paper is written, not what it is about, so requiring them throws away good papers (a paper about odor and AI rarely says "understand"). They are not sent to a source as required words. A result that contains one gets a small boost in relevance: it counts 0.3 in BM25, where a concept counts 1.0. The list is plain data in `packages/core/src/softterms.ts`, viewable in Settings, and is meant to hold only words that would be wrong to require in a search about *any* subject.
3. **Hard terms** are everything else. Each is a concept that a result **must** match. If a search has no hard term at all (for example `new novel approach`), every word that is not a common word is made hard, and "How we searched" says so.

Words that belong together become **one** concept. Each quoted phrase is one. So is a phrase the thesaurus lists as one (`machine learning`, `climate change`, `coral reef`, `double pendulum`, `immune system`, ... `KNOWN_PHRASES` in `thesaurus.ts`) when its words are typed next to each other. `CAN bus protocol` is three concepts, `CAN`, `bus` and `protocol`, because no phrase is listed.

**All-capital abbreviations** (two to six capitals or digits, such as `AI`, `ML`, `CNN`, `CAN`, `US`) are always hard, and are matched **with their capitals, as whole words**: `AI` does not match "Ai Weiwei", the lowercase `ai`, or the letters inside "waiting". A plural `-s` is allowed (`CNNs`).

**Common words.** The fixed list is exactly this:

```text
a about above after again against all also am an and any are aren arent as at be because been before being below between both but by can cannot cant could couldn couldnt did didn didnt do does doesn doesnt doing don dont down during each few for from further had hadn hadnt has hasn hasnt have haven havent having he her here hers him his how i if in into is isn isnt it its itself just ll me more most my no nor not of off on once only or other our ours out over own re same shall she should shouldn shouldnt so some such than that the their theirs them then there these they this those through to too under until up ve very was wasn wasnt we were weren werent what when where which while who whom whose why will with won wont would wouldn wouldnt you your yours
```

A query made only of common words, only of `NOT` terms, or empty is not sent anywhere, and the page says why.

**Nothing is hidden.** The text in the box is never changed, and the page has no chips under the box. Under the results heading, the collapsed **"How we searched"** lists: every concept with its variants (the ones that came from the thesaurus are marked with the kind of entry), the common words that were left out, the generic words that were set aside, the exact query each source received with what it could not apply, and whether a fallback ran. The search protocol records the same.

### The curated thesaurus

`packages/core/src/thesaurus.ts` is a hand-written list of about 220 entries: plain data, no model, nothing learned. Each entry says which other ways papers write the same word, and has a **type** and a **one-line note**:

- **spelling**: a US/UK or other spelling pair (`odor`/`odour`, `behavior`/`behaviour`, `analyze`/`analyse`, `modeling`/`modelling`). Works both ways.
- **abbreviation**: an abbreviation and what it stands for (`AI`, `ML`, `DL`, `CNN`, `GNN`, `NLP`, `LLM`, `CRISPR`, `COVID-19`, `MRI`, `EEG`, `PFAS`, `CAN` = controller area network, ...). Works both ways.
- **synonym**: a tight near-synonym or word form (`AI` = "artificial intelligence" or "machine learning" or "deep learning" or "neural network"; `odor` = odorant, olfaction, olfactory, sense of smell; `prediction` = predict, predicting, predictive, predicted, predictor; `climate change` = global warming). Works **one way**: the typed term brings its variants, a variant does not bring the term back (so `machine learning` does not drag in `AI`).

**What it deliberately does not do.** It does not drift. `odor` is *not* mapped to *aroma*, *flavor* or *fragrance*: a food paper about the aroma of apples is not a paper about odor perception. A synonym is added only when a paper would write it **instead of** the term, in the same sense. A concept gets at most 8 variants. A quoted phrase and an `OR` group are never expanded: quotes mean exactly this. Entries for word forms (`predict`, `predicted`) exist because there is no stemming (below); where a form is missing, it is not matched.

**Limits.** The list is short, so it covers common cases only, mostly science and engineering. A word with no entry has no alternatives; an ambiguous abbreviation (`CAN`, `PV`, `EV`) matches every meaning of its capitals; and a new field's vocabulary is missing until someone adds it. **Adding an entry** is described in [CONTRIBUTING.md](../CONTRIBUTING.md). The setting **"Expand with curated synonyms"** (Settings, on by default) turns the thesaurus off for the next search.

### How a result matches a concept

A result matches a concept if **any** of its variants appears as a **whole word or phrase** in its **title**, its **author keywords** or its **abstract**, and nowhere else (not in topic tags, MeSH headings, subject categories, OpenAlex's own keywords or the venue). The comparison is deliberately light: lowercase, accents folded, and a plural **-s or -es** taken off from 5 letters up. There is **no other stemming**. The details are under "Term coverage and tiers".

Every match can be checked by eye. A card says `Matched: odor (odour, title) · AI (machine learning, abstract)`: the concept, the variant that matched, and the field. "Why this rank?" shows, for each concept, about 80 characters of the text around the match with the match marked.

### Search exactly as typed

**Settings → "Search exactly as typed"** (off by default) sends your text to every source as you typed it: no common word is removed, no generic word is set aside, no alternative is added, no operator is written for you. Locally, words are then compared as they are: nothing is normalized or dropped, even for ranking, and every word you typed is required. There are no fallback passes. It was moved from the search box into Settings so the main view stays quiet.

### What each source is sent

Sources read the same concepts differently, and some of them look in the full text of every paper by default, which brings back works that only mention your words in passing. So the concepts are written once per source, with each concept as a group of alternatives and `AND` between the concepts, and the source is asked to look only in titles and abstracts where it can. "How we searched" shows exactly what was sent, with a note about anything the source could not apply. The forms below were checked against each source's current documentation and with test searches on 2026-10-14 and 2026-10-15:

| Source | What it is sent | What was found |
| --- | --- | --- |
| OpenAlex | `search.title_and_abstract=(AI OR "artificial intelligence" OR ...) AND (odor OR odour OR ...)` | OpenAlex documents `search.title_and_abstract` as "title and abstract text only". The plain `search` parameter also reads keywords and full text and returned works that only mention the words in passing. The scoped form accepts uppercase `AND`, `OR`, `NOT`, parentheses (also nested) and quoted phrases. At 100 results per source, two pages of 100 are fetched, one after the other (up to 200 works), because OpenAlex is the backbone. |
| PubMed | `("machine learning"[tiab] OR ML[tiab] OR ...) AND (odor[tiab] OR odour[tiab] OR ...)` | Without field tags PubMed applies *automatic term mapping*, which adds word forms and synonyms and can match the journal named like your word. A field tag turns that off, and each term must be tagged on its own. `[tiab]` (title and abstract) is the field that matches what Sourcly itself reads; `[tw]` also searches MeSH headings, which Sourcly does not count as a match. Checked on 2026-10-15: the AI × odor query above is accepted and is translated to `[Title/Abstract]` groups (1,324 matches). |
| Europe PMC | `(TITLE_ABS:"machine learning" OR TITLE_ABS:ML OR ...) AND (TITLE_ABS:odor OR ...)` | Unfielded searches read the full text of open-access papers. `TITLE_ABS:` restricts to the title and abstract and works inside groups (checked 2026-10-15: 1,482 matches for the AI × odor query). Its help pages could not be read (they sit behind an automated-access check), so this syntax rests on test searches and third-party documentation, not on Europe PMC's own text. |
| Crossref | The word you typed for each concept, as plain words, in `query.bibliographic`, **at most 20 rows**, only scholarly types | Crossref has no `AND`, no `OR` and no phrases. It is a **supplement** only: its order is loose, so the rows are cut so that its fuzzy matches cannot dominate the pool. **Every Crossref result passes the same local matching as any other**; one that does not match every concept goes to "Partial matches" (or to the "all but one" part of the list when few results match). |
| DOAJ, DataCite, Zenodo | Boolean: `"memory consolidation" AND sleep NOT rats` | `AND`, `OR`, `NOT`, quotes and parentheses worked on all three. Every `AND` is written out because DataCite and Zenodo document that words are otherwise optional. Only the word you typed for each concept is sent, with a note that alternatives are checked locally. |
| Wikipedia | Boolean, but a group of alternatives inside a larger search is left out, at most 5 pages | `sleep AND (nap OR rest)` finds exactly what `sleep` does, so the group is left out and the note says so. |
| Semantic Scholar | Plain words, with a hyphen written as a space | Its search endpoint takes plain text, and its API specification says hyphenated terms find nothing. This is taken from the specification; it could not be confirmed with a live answer, because the keyless pool refused the request (HTTP 429). |

A source that cannot take alternatives is sent the most specific form, the word you typed for each concept; the other variants are still used when the results are checked locally, so a paper that says "olfaction" is a match for "odor" if the source returns it.

### The candidate pool

Each source is asked for up to 100 results for the strict query (OpenAlex up to 200 in two pages), in the source's own relevance order. The results of all sources are merged, duplicates are combined, and each work lists the sources that found it (one badge per source, with its best rank). Everything Sourcly ranks is only what the sources returned (see limitations).

### Fallback passes

When the strict search is finished and **fewer than 15** merged results match every concept, Sourcly runs up to **three more searches, one concept dropped each**, without you asking. (The number 15 is a plain threshold, not a measurement.) Which concept goes first is decided by how specific it is: one small request to OpenAlex per concept (`per_page=1`, which returns the total number of works in `meta.count`; answers are remembered for the visit) says how many works match that concept alone. The concept that matches the **most** works narrows the search least, so it is dropped first. Without counts (for example OpenAlex is switched off), the concepts are dropped in the order typed.

The passes stop as soon as 15 distinct results match every concept or all but one, or when three have run. Their results are merged in, are never presented as full matches, and are labelled **"Matches N of M concepts"**; a result that only a pass found carries the label "Fallback search: not every concept matched". "How we searched" shows that a fallback ran, the counts it used and the exact query of each pass, and the search protocol records them. A search of one concept has nothing to drop.

### "Did you mean ...?"

After results arrive, the page checks whether a word of your search is probably a typing slip. It looks only at the results that came back (titles and abstracts), asks no service and uses no dictionary:

- Only plain words you typed on their own are checked: not words in quotes, hyphenated words, words with a digit, words inside a group of alternatives, words after `NOT`, words the thesaurus joined into a phrase, all-capital abbreviations, or words shorter than 4 letters.
- A word is a candidate when it is in no more than a tenth of the merged results (and never fewer than 3 are allowed). A word is looked for that is **within 2 edits** of it (an insertion, deletion, substitution or swap of two neighbouring letters counts 1; the Damerau-Levenshtein distance), **starts with the same letter**, is in **at least 5 results** and in **at least 3 times as many** results as the typed word (2 times for a word one edit away: on the real search for "caos double pendulum", "chaos" was in 8 results and "caos" in 3, while the two-edit word "case" was in 9). Of the candidates the nearest wins, then the one in the most results, then the first alphabetically.
- The suggestion is a link: **"Did you mean chaos double pendulum?"** with a line saying how many results have each word. **Nothing is changed or searched until you click it.** Clicking puts the suggested text in the search box and searches. Only the words that differ are replaced; operators, spacing and everything else stay as typed.
- It needs enough results to judge from: with few results, or none, there is no suggestion. It cannot suggest a word that no result contains, and it can be wrong.

### Suggested terms

Under the search box, a collapsed **"Suggested terms (N)"** offers terms you might add. They are not generated: they are the **author keywords** and **MeSH headings** of the **top 30 results of the main list** that occur in **at least 3** of those results (a term that one or two papers have is theirs, not the field's, so a count of 1 or 2 is never shown), at most 8, most common first (ties alphabetical). **It is shown only when there are at least 3 such terms.** The button shows the count and its tooltip says whether the term is an author keyword, a MeSH heading, or both.

- A term made only of words your search already covers (including every variant of a concept) is not offered.
- MeSH "check tags", the routine headings that NLM indexers add to say which species, age group, country or period a study concerns (`Humans`, `Adult`, `Mice`, and so on, 40 in all, listed in `packages/core/src/checktags.ts`), are left out. The list is taken from NLM Lister Hill Center's report "Check Tags MeSH Terms Indexing Research Project".
- OpenAlex topics and OpenAlex's own keywords are not used: the first are algorithmic labels, the second came from a classifier, and both brought unrelated terms such as "Bacterial Proteins" into earlier versions.
- **Choosing a term only adds it to the search box**, as one more concept (in quotes if it has several words; the existing query is put in parentheses first if it has an `OR`). Nothing is searched, and nothing is added to the query behind your back: you press Search yourself.

Because they come from the top results, the suggestions inherit the ranking's biases, and they lean towards biomedicine, where MeSH exists.

**Search elsewhere** links use the text you typed. Operators such as `NOT` are passed through as written, and other search engines may read them differently.

## Merging duplicates across sources

Two records are the same work when they share a **DOI**. A DOI that differs only by a trailing version marker (`.v1`, `/v2`) counts as the same, because repositories such as figshare and Zenodo register a version DOI and a concept DOI for one deposit.

Failing that, two records are the same work when their **normalized title, publication year and first author's family name all match**. Titles are compared ignoring case, accents, punctuation and markup. Names are compared by family name, whether written "Robert Stickgold", "Stickgold, Robert" or "Stickgold R". A record with no listed author, or a title shorter than eight characters, is matched by DOI only, because a title alone is too weak a sign.

Two records whose DOIs differ are **never** merged, even with an identical title: they may be a preprint and its published version, which are different works that you may want to see separately.

When sources disagree about a merged work, the rule is the same every time:

| Field | Which value is kept |
| --- | --- |
| Title, year, venue, volume, issue, pages, language, link | From the source earliest in this order that has one: OpenAlex, Crossref, Europe PMC, PubMed, Semantic Scholar, DOAJ, DataCite, Zenodo, Wikipedia (each of volume, issue and pages is taken on its own, so they can come from different sources) |
| Authors, abstract | The longest |
| Citation count | The highest any source reported (sources index different citing works, so the largest count is the most complete) |
| Type | The most specific: review, then journal article, conference paper, preprint, thesis, book, book chapter, reference entry, report, dataset, other, unknown. The label's reason quotes the source that gave it |
| Open access | Open if any source says so, with that source's link and PDF |
| Retraction | Retracted if any source says so, listing each source; otherwise "not retracted" if any source says so |
| Author countries | All of them |

The card shows "Found by" for every source, and the provider agreement factor counts them. Subject terms (topics, keywords and MeSH headings) from every source are combined too, without repeats.

## When sources are slow, busy or unavailable

Every source gets its own status line, so a gap in the results is never silent:

- **ok**: it answered (with how many results), or the answer was remembered from earlier in the visit.
- **rate-limited**: the source answered HTTP 429, meaning you have used its allowance for now.
- **failed**: it could not be reached, took longer than 15 seconds, or sent something unreadable. The message says which.
- **skipped**: the source was not asked, with the reason (arXiv, below).

One source failing never affects the others. Searching the same words again within a visit reuses each source's earlier answer instead of spending its limit a second time. This memory exists only in the page: nothing is written to your device, closing the page clears it, "Forget remembered results" in Settings clears it, and a failed or rate-limited answer is never remembered, so retrying really retries.

## Filters

Filters are optional, and none is set by default. They hide results; they never change a score.

| Filter | Keeps |
| --- | --- |
| Year from / to | Results published in that range, both ends included. Either end can be left empty. A result with no publication year is hidden as soon as either end is set, because it cannot be shown to be inside the range. |
| Level | Results whose level label is one of the ticked levels. Nothing ticked means all. |
| Peer review | Results whose peer-review label is one of the ticked statuses. Nothing ticked means all. |
| Open access only | Results the provider says are free to read. A result with no open-access information counts as not open. |

All ticked filters must be satisfied (they combine with "and"). Filters use the labels you see, including any you changed by hand.

Scores are worked out over every fetched result first, and filters are applied afterwards. That is why a filter cannot change anyone's score or rank, and why the citation percentile does not shift when you filter. The page always says how many results your filters are hiding and offers a "Clear filters" link.

Language and type are not filters: they decide a result's section, and nothing in a section is hidden (see the next two sections).

## The main list and its sections

Results are ordered by, in this order: **how many of your concepts they match** (tier 1: every concept; tier 2: more than half; tier 3: half or fewer), and inside a tier the number matched; then **whether neighbouring concepts of your search are next to each other, in order, in the title or abstract** (the phrase match, 1 for a pair in the title, 0.7 in the abstract); then the **weighted score**. Equal on all of them, the DOI orders them. "Why this rank?" on every card shows each of them and the section.

Each result then goes to one place, decided by these rules in this order:

1. **Datasets, presentations and other types** (collapsed section). A dataset, thesis, report, reference entry or other non-article type, and any work that only Zenodo or DataCite holds, however its type is written. Articles, reviews, preprints, conference papers, books, book chapters, and records whose type is unknown stay out of this section. Unknown stays out because a guess would hide good results. The setting **"Show non-article types in the main list"** (off by default) turns the section off.
2. **Other languages** (collapsed section). A result whose language is known (see "Language detection") and is not one of your **preferred languages**, chosen in Settings (default: English; several can be ticked; none ticked means any). A result whose language could not be told stays where its words put it.
3. **The main list.** Results that match **every** concept. If **fewer than 15** results (among those not in the two sections above) match every concept, results that match **all but one** join them, **below the full matches**, each labelled **"Matches N of M concepts"**. This needs at least two concepts: with one, "all but one" would be none of it.
4. **Partial matches** (collapsed section). Everything else: results that lack more than one concept.

A result is in exactly one of the four places or hidden by a filter you set. Each section shows a count, the same cards, its own pages and a sentence saying what it holds. Sections never change a score or a tier.

## Language detection

A source's language field is not trusted by itself: OpenAlex labelled a Vietnamese-titled paper "English". So the language of every result is also **detected from its title and the start of its abstract** (the first 1,500 characters) by rules, with no model and nothing learned:

1. **Script.** If enough of the letters belong to one script: any Hiragana or Katakana (10% or more of the letters) is Japanese; Hangul (30%) Korean; Han characters without kana (30%) Chinese; Cyrillic (50%) is reported as Russian (Ukrainian, Bulgarian and others are not told apart); Greek, Arabic, Hebrew, Thai and Devanagari (Hindi), 50% each.
2. **Latin letters.** Otherwise, for English, Spanish, Portuguese, French, German, Italian, Vietnamese and Turkish, each language scores the common words it has in the text (about 40 words each, in the source code: a word in only one language's list counts 2, a word shared by several lists counts 1) plus 3 for each letter that marks the language (Vietnamese tone marks and đ ơ ư ă; Turkish ğ ş ı; Spanish ñ ¿ ¡; Portuguese ã õ; German ß; French œ).
3. **A language is named only when the evidence is clear**: its score is at least 3 and at least 2 ahead of the next language. Otherwise the language is "not detected".

Then it is compared with what the sources say:

- the text says X and a source says X, or says nothing: **"Language: X (detected)"**;
- the text says nothing clear and a source says X: **"Language: X (from the source)"**;
- the text says X and a source says Y: **"Language unclear"**; the result is placed by what the text says, and the tooltip names both;
- neither says anything: **"Language: unknown"**.

**Limits.** Short texts are the weak case: "Chaos in a double pendulum" has too few common words to be detected, so it falls back to the source (and is "unknown" for a Crossref record, which carries no language). Text mixing languages, an abstract in one language with a title in another, and languages outside the list (Dutch, Polish, Indonesian, Czech and so on, which are Latin script) are not detected, and a text in an unlisted language that shares words with a listed one can be named wrongly. Code, formulas and names in a text can tip a short one. The method is meant to catch the plain cases, like the Vietnamese and Spanish papers that were polluting English searches, not to be a language identifier.

## Looking up one work (DOI, link, ID or title)

The search box recognises what was typed, by plain rules and without any network request (`parseInput`):

| Typed | Detected | Looked up as |
| --- | --- | --- |
| `10.1038/s42004-024-01373-2`, `doi:10.1038/...`, `https://doi.org/10.1038/...` | DOI | that DOI |
| A publisher address with the DOI in it (Springer `/article/10....`, Wiley `/doi/full/10....`, Taylor & Francis, PNAS, science.org `/doi/10....`, an address with `?doi=10....`), including `.pdf` and `/full` endings | DOI | the DOI found in it |
| `https://www.nature.com/articles/<id>` | DOI | `10.1038/<id>` (Springer Nature's article address is its DOI's suffix) |
| `2304.00997`, `arXiv:2304.00997v2`, `https://arxiv.org/abs/2304.00997`, `hep-th/9901001` | arXiv ID | its DOI, `10.48550/arXiv.<id>` (arXiv gives every paper one, and OpenAlex knows them) |
| `PMID: 29456894`, `https://pubmed.ncbi.nlm.nih.gov/29456894/` | PubMed ID | that PMID |
| `PMC5815332`, a PubMed Central or Europe PMC address | PubMed Central ID | that PMCID |
| `W2741809807`, `https://openalex.org/W2741809807` | OpenAlex ID | that work |
| Any other address | link | OpenAlex's landing-page filter (below) |
| Eight or more words, no `AND`/`OR`/`NOT`, no quotes or brackets, no question mark and not starting with a question word | title | the ordinary search, plus "Closest match for this title" |
| Anything else | keywords | the ordinary search |

A bare number such as `29456894` is **not** taken as a PubMed ID (it could be any number); write `PMID: 29456894`.

Under the box the page says **"Detected: DOI. Pressing Search looks it up. Search as keywords instead"**; the link switches the text back to being searched as keywords (and a second link switches it forward again). The text in the box is never changed.

**What a lookup does.** Plain requests, directly from your browser, to sources that allow it: **OpenAlex** (`works/doi:...`, `works/pmid:...` or `works/W...`), **Crossref** (`works/<doi>`), **Unpaywall** (`/v2/<doi>?email=...`), and for a PubMed ID also **PubMed** and **Europe PMC**; for a PubMed Central ID **Europe PMC**. The answers are merged into one record the way search results are. Unpaywall requires an email address with every request (checked 2026-10-15: without one it answers HTTP 422), so it is asked only when a contact email is set in `config.js`; otherwise the page says so, and OpenAlex's open-access information, which comes from the same data, is used. A free PDF link is only ever taken from a location the source says is open.

**Links Sourcly cannot read.** A browser cannot fetch an arbitrary web page (the page would have to allow it, and almost none do), so Sourcly does not fetch pages, does not scrape them and uses no proxy. An address that is not a DOI, an ID or a publisher address with a DOI in it is looked up only by its **address**, in OpenAlex, with the filter `locations.landing_page_url` (checked 2026-10-15: a made-up filter name is refused with HTTP 400, and `primary_location.landing_page_url` also exists), trying the address with and without `www.`, with `https` and `http`, and with and without a trailing slash. OpenAlex usually stores a work's DOI link as its landing page, not the publisher's page, so many publisher addresses are not found this way, and then the page says: **"Could not identify this link. Paste the DOI or the title."**

**The card.** A lookup shows one detailed card at the top: the title, authors, year, venue with volume, issue and pages, the labels with their reasons (and "Change labels"), the retraction badge and a warning, the open-access status and, when known, a link to a free PDF, "Access with UBC Library" (when configured), the DOI, "Save to list", the abstract (open), and a list of everything the sources say. It has no score and no "Why this rank?", because nothing was searched. Below it are three buttons, which load lists from OpenAlex when pressed: **Show its references** (`filter=cited_by:W...`, the works this work cites), **Show works citing it** (`filter=cites:W...`) and **Related papers** (the works OpenAlex lists as related, `filter=openalex:W1|W2|...`). Up to 100 of each are asked for, most cited first, and shown with the ordinary cards, labels and "Why this rank?". With no search words behind them, word matching does not apply, and they are ordered by the weighted score.

**A long title.** For eight or more plain words, the ordinary search runs, and above it a **"Closest match for this title"** card appears: Crossref's bibliographic search and OpenAlex's relevance search are both asked for their top 5, the answers are merged, and the one whose title is most like yours wins if the titles are at least 70% alike (measured by the words of the shorter title that the longer one has, ignoring common words, with a small penalty when the other title is much longer). The percentage is shown on the card. If no title is close enough, the page says so.

## Source labels

Every result carries two independent labels. Both are shown as "likely", with a one-line reason and the metadata field used. When the metadata is not enough, the label is **unknown**; we never guess silently. You can override any label on any result, and an overridden label is marked as set by you.

**Axis 1: level.** primary, secondary, tertiary, other or unknown.
**Axis 2: peer review.** peer-reviewed, not peer-reviewed or unknown.

### Rules

The rules read only the document type and venue type that the provider reports. They never read the title or abstract.

| Document type | Level | Peer review | Reason shown |
| --- | --- | --- | --- |
| Review (literature review, systematic review, meta-analysis) | secondary | peer-reviewed if in a journal, otherwise unknown | Review article, so it summarizes other studies |
| Journal article that is not a review | primary | peer-reviewed if in a journal, otherwise unknown | Journal article, not a review |
| Preprint | primary | **not** peer-reviewed | Preprint: reports original work / posted before peer review |
| Conference paper | primary | unknown | Conference paper: usually reports original work |
| Book | tertiary | unknown | Book: usually synthesizes other sources |
| Reference or encyclopedia entry | tertiary | unknown | Reference or encyclopedia entry |
| Book chapter | **unknown** | unknown | Could be original work, a review or a summary, and the metadata does not say |
| Thesis or dissertation | other | unknown | Thesis or dissertation |
| Report or working paper | other | unknown | Issued outside the journal system |
| Dataset | other | unknown | Dataset, not a paper |
| Editorial, letter, erratum, retraction notice, peer-review report, software, standard, supplementary material, book review, conference abstract, and similar | other | unknown | Not a research article, review or reference work |
| Anything else, or no type | unknown | unknown | No document type, or one we cannot classify |

"Peer-reviewed if in a journal" means: the record's venue type is "journal". The reason shown says that journals normally peer-review articles but that the record does not confirm it. If the venue is a repository or its type is missing, peer review stays unknown.

Three of these rows are judgment calls, not facts, and you may disagree with them:

- **Journal articles are treated as peer-reviewed** when they appear in a journal. Most are, but metadata cannot prove it.
- **Books are tertiary.** A monograph in the humanities can be a primary source for the right question. This follows the common STEM guidance that textbooks and reference works are tertiary.
- **Book chapters are unknown**, because in an edited volume a chapter can be any of the three.

One source is labelled by who it is, not only by its type: **Wikipedia** is tertiary (an encyclopedia) and **not peer-reviewed**, with the reason "Wikipedia is written and edited by volunteers, not peer reviewed".

Retraction is not a label. It is a separate badge, so a retracted article keeps its level and peer-review labels.

## Ranking

```
score = sum(weight_i * factor_i) / sum(weight_i)
```

The sums run over the factors you have switched on. Every factor is first normalized to a number from 0 to 1, so the score is also between 0 and 1. Only the proportions between weights matter: multiplying every weight by 10 changes nothing.

**The score is not the only thing that decides the order.** Before the score is used, results are put in three tiers by how many of your search's concepts they match (see "Term coverage and tiers" below), and ordered by whether neighbouring concepts are next to each other (see "The main list and its sections"). The score then orders the results that are equal on all of those. Where a result is placed (the main list or a collapsed section) is explained there too.

For each factor, the "Why this rank?" panel shows the raw value, the normalized value, the weight and the contribution (`weight * normalized / sum of weights`). The contributions add up to the score.

### Factors

| Factor | Raw value | Normalized to 0..1 |
| --- | --- | --- |
| **Relevance (BM25)** | The BM25 score of the result's title, abstract and author keywords against the concepts of your query (each concept counts 1.0, each generic word 0.3), worked out over all the merged results (formula below). | The score divided by the best score in the set, so the best match is 1 and a result with none of your concepts is 0. |
| **Term coverage** | Which concepts of your search the result matches, and where: `chaos, double pendulum (2 of 2)`. | The mean over the concepts of how strongly each was found: 1 if it is in the title, 0.8 in the author keywords, 0.6 if only in the abstract, 0 if not found. A concept found in the title and abstract counts as in the title. |
| **Phrase match** | How many pairs of neighbouring concepts in your search are also next to each other, in the same order, in the result's title or abstract: `1 of 2 pairs`. | The mean over the pairs: 1 for a pair in the title, 0.7 if only in the abstract, 0 if not found together. |
| **Citations** | Citations divided by years since publication (at least 1 year). | Percentile rank among the results that have citation data, counting ties as half. A log scale is not applied because it cannot change a percentile rank. |
| **Recency** | The publication year. | `0.5 ^ (age / half-life)`, where age is the current year minus the publication year (never below 0) and the half-life is 10 years by default. A paper from this year scores 1, one from 10 years ago 0.5, one from 20 years ago 0.25. |
| **Peer review** | The peer-review label (including your overrides). | peer-reviewed = 1, unknown = 0.5, not peer-reviewed = 0. |
| **Open access** | Whether the provider says the work is free to read. | open = 1, otherwise 0. A result with no open-access information counts as 0. |
| **Provider agreement** | How many of the sources that answered returned this result. | That number divided by the number of sources that answered, so found by every source is 1. |
| **Study type** | The level label (including your overrides). | If you chose preferred levels: 1 if the result's level is one of them, otherwise 0. If you chose none: 0.5 for every result, so it has no effect. |

**Missing data is neutral, not bad.** If a result has no year or no citation data, the factor scores 0.5 and the panel says so. Relevance scores 0.5 for every result when the query has no searchable words, term coverage scores 0.5 when the query has no concepts to look for, phrase match scores 0.5 when the query has no two neighbouring concepts (a single concept, or concepts joined by `OR`), and provider agreement scores 0.5 when fewer than two sources answered, because there is nothing to compare. (Open access is the exception, which the table above explains.)

### Term coverage and tiers

Every provider matches words loosely (some match any one of your words, some look in the full text, some correct spelling), so a result can come back that has little to do with what you typed. Sourcly therefore checks, itself and in your browser, which of your concepts each result actually matches.

**Where concepts are looked for.** In the **title**, the **author keywords** and the **abstract**, and nowhere else. Not in the venue (a journal called *CAOS* does not match "caos"), and not in topic tags, MeSH headings, subject categories or OpenAlex's own keywords: those are labels a source attached to the work, not words of the work. The author keywords are the ones PubMed, Europe PMC, DOAJ, Zenodo and DataCite carry; OpenAlex's keywords come from its own classifier and are not counted. A concept in the title counts 1, in the author keywords 0.8, only in the abstract 0.6 (this is the weight in the "Term coverage" factor).

**What counts as a concept.** Each hard block of "Writing a search": a quoted phrase, a phrase the thesaurus joins, or any other content word; an `OR` group is one concept that either side satisfies. Words after `NOT`, common words and generic words are not concepts. The optional "any of these" group the counterarguments panel adds is not one either, so it never decides coverage.

**A concept matches if any of its variants does.** A concept is the word you typed plus the thesaurus variants. `odor` is matched by `odor`, `odour`, `odorant`, `olfaction`, `olfactory` or the phrase `sense of smell`. The bare word `smell` is left out on purpose: it is also what software engineers call a code smell, and with it a live search for "How AI understand odor" (2026-10-15) returned 13 code-smell papers among its first 70 results (typing `smell` yourself still brings `odor`, `odour`, `olfaction` and `olfactory`). The card says which one matched and where (`Matched: odor (olfactory, title)`), and a variant that came from the thesaurus is marked in "Why this rank?".

**How words are matched.** Whole words only, on word boundaries: text and query are split at anything that is not a letter or digit, lowercased and stripped of accents, and each word is compared in its **normalized** form (below). `pend` does not match `pendulum`, and `ring` does not match `string` or `spring`. A phrase, and a word with a hyphen in it (`self-organizing`), is found only when its words appear next to each other, in that order, in one field, with only a space, hyphen or slash between them; it cannot run from one author keyword into the next. The words of a quoted phrase keep their common words (`"to be or not to be"`). **An abbreviation in capitals is matched with its capitals, as a whole word**: `AI` matches "AI" and "AIs", not "Ai Weiwei", "ai", "AIDS" or "waiting". With "Search exactly as typed", nothing is normalized and nothing is dropped.

**Normalization** (`normalizeWord`). The same conservative steps are applied to your words and to every result, so they always agree:

- a word of **fewer than 5 letters is left exactly as it is**: `caos` is not `cao`, and `cats` is not `cat`;
- a plural **-s or -es** is taken off from 5 letters up: `memories` to `memory`, `processes` to `process`, `models` to `model`, `boxes` to `box`. Words ending in -ss, -us or -is are left alone (`stress`, `status`, `analysis`), as are a few singular words that end in s (`chaos`, `bias`, `series`, `species`), and the irregular plurals academic writing uses are folded (`analyses`, `hypotheses`, `diagnoses`, `theses`, `biases`);
- **nothing else changes. There is no stemming**: `predicting`, `predicted` and `prediction` are three different words, `learned` is not `learn`, `chaotic` is not `chaos`. An earlier version folded `-ing` and `-ed` too; it was removed because it made unrelated words equal and could not be checked by eye. Where a paper may write another form, the thesaurus lists it (for example `prediction` brings `predict`, `predicting`, `predictive`, `predicted`, `predictor`), and a form that is not listed is not matched.

Porter's stemmer was not used: it also cuts endings like `-ation` and `-ity`, which joins unrelated words (`university` and `universal`). The price of being conservative is that a word form nobody listed is missed.

**Tiers.** A result is in tier 1 if it matches every concept, tier 2 if it matches more than half of them, tier 3 if it matches half or fewer. For three concepts: 3 of 3 is tier 1, 2 of 3 is tier 2, 1 of 3 is tier 3; for two, only 2 of 2 is tier 1. Inside a tier, results that match more concepts come first, then the phrase match, then the score. The order you typed the concepts in does not matter: `chaos double pendulum` and `double pendulum chaos` put the same results in tier 1.

**On the card.** Every result says `Matched: odor (odour, title) · AI (machine learning, abstract)  (2 of 2)` and, if some concepts were missing, `Not found: …`. The places where concepts matched are marked in the title and abstract. "Why this rank?" lists the tier, the phrase match and the section, and, for each concept, the variant that matched, the field and about 80 characters of the text around it.

**Two factors, so you can weigh them.** The tier and the phrase match decide the order first; the "Term coverage" factor then rewards the strongest matches inside the score (a concept in the title is worth more than one buried in the abstract), and the "Phrase match" factor rewards results that use neighbouring concepts together. Both are ordinary factors: switch them off or change their weights in Settings like any other. The tier, the phrase order and the sections do not change when you do.

**Phrase match.** For `machine learning odor prediction` the pairs are `machine learning odor` and `odor prediction` (each pair of neighbouring concepts), and a pair counts when some variant of the first ends right where some variant of the second begins. A result with "machine learning odor" in its title scores 1 for that pair; one that only says it in the abstract, 0.7; one that has them apart, 0. The phrase match is the mean over the pairs. Keywords are not searched for pairs, because they are short lists, not running text.

### Relevance: BM25

Relevance is no longer taken from a source's own ranking (each source ranks differently, and some give no score). Sourcly scores every result itself with BM25, a standard word-matching formula from information retrieval, in your browser. It uses no learned model and no network: the same results and query always give the same scores.

**What is matched.** For each result, the text is its title, its abstract and its author keywords. Nothing else is read: not topic tags, MeSH headings, authors, venue or full text. The "terms" BM25 counts are the **concepts** of your search: how many times any variant of a concept matches in the result is that concept's term frequency. Each concept counts **1.0**. The **generic words** (soft terms such as "understand" or "using") are counted as terms too, at weight **0.3**, so a result that has them is lifted a little, and one that lacks them loses nothing it was owed. Words you excluded with `NOT` are not counted, and BM25 does not enforce `OR` or `NOT`; the sources already applied those, and the concept matching enforces the rest.

**Words.** Text and query are split the same way: lowercase, accents removed, split at anything that is not a letter or digit, apostrophes dropped, and each word normalized as described under "Term coverage and tiers" (a plural -s or -es is folded; nothing else). A result's length is its number of words in the title, keywords and abstract.

**Formula.** For a term `t` (a concept or a generic word) with weight `w(t)` (1.0 or 0.3) and a result text `d`, over the `N` merged results:

```
idf(t)      = ln(1 + (N - n(t) + 0.5) / (n(t) + 0.5))
score(t, d) = w(t) * idf(t) * tf(t, d) * (k1 + 1) / (tf(t, d) + k1 * (1 - b + b * |d| / avgdl))
BM25(d)     = sum of score(t, d) over the terms
```

`n(t)` is how many results match `t`, `tf(t, d)` how many times `t` occurs in `d`, `|d|` the number of words in `d` and `avgdl` the average over all results. **Parameters: `k1` = 1.2 and `b` = 0.75**, the usual defaults. `k1` sets how fast repeating a word stops helping, and `b` how much a long text is discounted against a short one. The relevance factor is `BM25(d)` divided by the highest `BM25` among all merged results (before any filter, so a filter never changes a score).

Three things follow, and "Why this rank?" shows the numbers so you can see them happen: a **rarer concept counts for more** among the fetched results; a word repeated many times **does not keep adding**; and a result with a **long abstract is discounted** against a short one. The panel gives the raw BM25 score, the best score, the result as a share of it, and which concepts matched and how often.

**Because it is worked out over the fetched results, scores can change when the set changes**: when another source answers, when you change the sources or the number of results per source, or when you search again. The best match is always 1, so 1 means "the best of these", not "a good match".

### Provider agreement

The share of the sources that answered which returned the result: found by 3 of the 6 sources that answered is 0.5. A source that answered with nothing counts as answered; one that failed, was rate-limited or was skipped does not. It is neutral (0.5) when fewer than two sources answered. The panel names the sources that found the result. The idea is that a work several independent databases all return is a little more likely to matter, but it is only a hint, which is why the default weight is small (see limitations).

### Default weights

| Factor | Weight | Why |
| --- | --- | --- |
| Relevance (BM25) | 3 | A source that does not match your question is useless however well cited, so matching comes first. |
| Term coverage | 2 | Among results that contain every term, one with the terms in its title is more likely to be about them than one that mentions them in passing in the abstract. (Which tier a result is in is not a weight: it always comes first.) |
| Phrase match | 1 | "double pendulum" together is a better sign than "double" and "pendulum" in different sentences, but it is only a sign, so it is weighted below coverage. |
| Citations | 1 | A sign of influence, but biased (see below), so it only nudges. |
| Recency | 1 | Newer work matters in many fields, but old work is often foundational. |
| Peer review | 1 | A useful signal, but based on a heuristic label. |
| Open access | 0 | Institutional library access makes open access much less relevant for ranking. With UBC Library access you can read most paywalled sources as easily as free ones, so "is it free?" says little about whether *you* can use it, and counting it would push good sources down just because their publisher charges. The factor is still switched on and its value still shown, but at weight 0 it changes no score. If you do not have library access, raise the weight in Settings. |
| Provider agreement | 0.5 | A small nudge: databases overlap and cover different fields, so agreement is only a weak sign (see limitations). |
| Study type | 0 (off) | Sourcly cannot know which kind of source your assignment needs, so you decide. |

The weights add up to 9.5 (3 + 2 + 1 + 1 + 1 + 1 + 0.5), so relevance, coverage and phrase match together are about two thirds of a score. These are starting points, not truths. Change them freely.

### Ties and determinism

Results are ordered by tier first, then by the number of concepts matched, then by phrase match, then by score. Results in the same tier with equal scores are ordered by DOI (or internal id), compared by plain character codes, so the order never depends on your language settings or on the order providers answered. BM25 does not depend on the order results arrive in either. If you switch every factor off, every score is 0 and the order is simply by DOI/id.

## Counterarguments & limitations

A second section on the page looks for sources that discuss the limits of your topic, criticism of it, or corrections to it. **It starts as a small bar** above the results (the heading, the notice below and an Open button) and opens when you press Open. Opened, it moves into a second column beside the main results on a wide screen (1000 pixels or more), and stays above the results on a narrow one. The rest of the time the whole page is one centred column; it widens only while this section is open, to make room for the second column. Closing it hides it but keeps your terms, your own search text and any results, and the bar says how many results the last search found. It always carries this notice, closed or open, in the app and here:

> Keyword-based: this finds sources that discuss limitations or criticism. It cannot tell whether a source actually disagrees. Read before citing.

**It runs only when you press its button.** It is a second search, so it sends another round of requests to every source (about as many again, and OpenAlex's keyless allowance is only about 100 searches a day). Starting a new main search clears its results, and keeps your terms.

**Two ways to search.**

1. **Your search, narrowed by terms** (the default). The query is your main search plus "any of these terms", for example `sleep memory (limitation OR criticism OR "no evidence" OR ...)`. A result has to match your whole search and at least one term.
2. **Only my own search.** Whatever you type, read by the same rules as the main search box (so common words, including `not` and `does`, are removed: write the claim as keywords such as `hydroxychloroquine ineffective`). Use it to search for an opposing claim directly.

**The terms.** They are defined in `packages/core/src/counter.ts` and shown as chips you can remove, add to, or reset. They are plain keywords, not a model of disagreement:

| Group | Terms |
| --- | --- |
| Limitations and criticism | limitation, criticism, challenge, fail, failure, bias, reproducibility, replication, controversy, "no evidence", "negative results" |
| Corrections and withdrawals | retraction, erratum, corrigendum |

A term is a word or a short phrase of letters and digits (at most 60 characters, quotes removed). A lone common word such as `the` is refused with the reason. The terms are matched as whole words with their plurals, in any capitals and ignoring accents, so `limitation` matches `Limitations` but not `limited`, and `fail` does not match `failed` or `failure` (that is why both `fail` and `failure` are listed, and why `bias` also matches `biases`). A phrase matches across spaces or a hyphen but not across a full stop. If you want another form, add it. The terms in the chips when you pressed the button are the ones used for ranking and marking; changing the chips afterwards changes nothing until you search again, and the panel says so.

**What each source receives.** For sources that read Boolean syntax the query is `sleep AND memory AND (limitation OR criticism OR ... OR "no evidence")` (with `[tiab]` or `TITLE_ABS:` on every word for PubMed and Europe PMC). Crossref and Semantic Scholar cannot say "any of these" (and Wikipedia ignores such a group inside a larger search), and sending them 14 extra words as a plain search returned unrelated records that happened to contain several of the words (found while building this panel), so they are sent only your search, and the panel says so; results of theirs that contain no term rank lower. "How we searched" shows every one. A single term is not optional: "any of one term" is that term, so every source is sent it.

**How the results are ranked.** The same factors and the same "Why this rank?" panel as the main list, with one change to relevance. Counting the terms among the query's words in an ordinary BM25 let a result about something else rank first just because its abstract used many of them (seen in a real search: a paper on research reproducibility topped a search about hydroxychloroquine). So here relevance multiplies two BM25 readings, each divided by the best in the set:

```
relevance = (BM25 of your search words) x (BM25 of the terms)
```

The second reading counts each term (a phrase counts as one) in the title and abstract, with the same formula and parameters as above. A result has to match both your search and a term to score above 0 for relevance; one that matches only one scores 0 (its other factors still count). If no result contains any term, only the first reading is used, and the panel says that. In "Only my own search" mode there are no terms in the query, so relevance is the ordinary BM25. The panel shows both readings and the product.

**Marking.** In each card, the terms found in the title and the abstract are highlighted (bold, underlined, grey background), and a line lists them: "Counterargument terms found: limitation (abstract), bias (title and abstract)". Only the title and the abstract are read; a source may have matched a term in the full text, which is not shown.

**Reviews, meta-analyses, retractions and corrections.** Three buttons above the results, each with a count, list only: *All*, *Reviews and meta-analyses*, or *Retractions and corrections*. Nothing is hidden unless you press one, no score changes, and a result can be in both of the last two.

- A **review** is a result whose type the source says is a review (PubMed's Review, Systematic Review and Meta-Analysis publication types, OpenAlex's `review`, and so on). Its card shows a "Review" badge, or the source's own wording ("Systematic Review", "Meta-Analysis").
- A **retraction or correction notice**, and an **expression of concern**, is a record about another article rather than research. It is recognised by how its title begins, because that is how publishers write them: `Retraction:`, `Retraction notice:`, `Retraction Note:`, `Retraction—`, `Retraction and Republication:`, `Notice of Retraction:`, `Withdrawn:`, `Erratum`, `Corrigendum`, `Correction:`, `Correction to:` or `Correction to "`, `Author Correction`, `Publisher Correction`, `Expression of concern`. These forms were checked on Crossref and OpenAlex records on 2026-10-14. A source's own type is not used: OpenAlex files research papers such as "Self-interaction correction to density-functional approximations" under its `erratum` type. Titles such as `Retraction of axons in the developing spinal cord`, `Correction of flux measurements...` and `Withdrawal symptoms in...` are not notices, because a notice has a separator (or `to` and a quote) after the word. The card shows a badge ("Retraction notice", "Correction notice", "Expression of concern") and says to find the article it concerns and read both. This badge appears on every card, in both lists.
- A **retracted work** is a work a source says was retracted (the existing RETRACTED badge: OpenAlex's `is_retracted` from Retraction Watch, PubMed's retraction records, Crossref's `updated-by`). It is listed with the notices under *Retractions and corrections*. A publisher's "RETRACTED ARTICLE: ..." record is a retracted work, not a notice: Crossref lists a retraction `update-to` on it that points at the article itself, so Sourcly counts a record as a notice only when that entry names a different work.

The notice terms in the default list (`retraction`, `erratum`, `corrigendum`) are there so that notices about your topic can be found at all; a notice whose title has none of your terms is only found if a source returns it for your search.

## The saved list

Every result card has a **Save to list** button (in the main results and in the counterarguments panel). Pressing it again removes the source. The **Saved list** panel under the search box shows what you saved, as the APA 7 references that will be exported, with the things to check under each one, a small **Access with UBC Library** link (built exactly like the one on the cards, from `libraryProxyPrefix` in `config.js`; hidden if that is empty), a link to remove it, and the buttons to copy, download or clear the list.

- **Where it is kept.** In this browser's `localStorage`, under the key `sourcly.savedList`, so it is still there next visit. It is never sent anywhere, and Sourcly has no account to sync it to: another browser, another device, a different profile, or clearing the site's data starts with an empty list. If the browser refuses to store it (private browsing, blocked site data, a full quota) the panel says the list will be lost when the page closes.
- **What is kept.** A snapshot of each result as it was when you saved it (title, authors, year, venue, volume, issue, pages, DOI, link, type, citation count, open-access and retraction information, and which sources found it), without the abstract and subject terms, so a reference can be made without searching again. Your label overrides are not saved. At most 500 sources.
- **It is untrusted on the way back in.** Everything read from storage is checked field by field: a damaged item is dropped, a wrong type becomes unknown, and only `http` and `https` addresses are kept, so edited storage cannot put a script address on a link.

## References (APA 7)

The saved list is exported as an APA 7 reference list by a small formatter in `packages/core/src/apa.ts`, built only from the fields Sourcly collects. **Copy references** puts the list on the clipboard as HTML (italics and a hanging indent, which Word and Google Docs keep when you paste) and as plain text. **Download references (.txt)** saves plain text, which has no italics, so you italicise journal names and volumes in your document. Where a browser cannot do the rich copy, it copies plain text and says so.

The rules followed:

| Element | Rule |
| --- | --- |
| Author names | `Family, G. M.`: family name, then initials with full stops and spaces. Hyphenated given names keep the hyphen (`Sartre, J.-P.`). `Jr.` and `III` go last (`King, M. L., Jr.`). Names in the form `Given Family`, `Family, Given` and `Family G` are all read, with `van`, `von`, `de`, `la`, `bin` and a few other particles kept with the family name. Names that look like an organisation (University, Institute, Organization, Consortium, ...) and one-word names are written whole. |
| How many authors | One author alone; two joined by `, &`; three to twenty with a comma and `&` before the last; **twenty-one or more: the first nineteen, then `. . .`, then the last author, with no `&`**. |
| No author | The title moves to the author position: `Title. (2020). *Journal*, ...` |
| Date | `(2020)`, or `(n.d.)` when there is no year. Works by the same authors in the same year get `2020a`, `2020b` in title order. |
| Title | Shown as the source gave it, with a final full stop added unless it ends in `?` or `!`. **It is not converted to sentence case**, which APA 7 asks for: a program cannot tell proper nouns from other words, so a title that looks like Title Case is flagged for you to fix. Markup in a title is removed (some sources send `<i>` tags, even as text), so italics inside titles, such as species names, are not kept: italicise them yourself. |
| Journal article | `Author. (Year). Title. *Journal, volume*(issue), pages. https://doi.org/...` The journal name and the volume are italic (the issue is not). An article number is written `Article e0173456` in place of pages. Journal names that PubMed gives in lower case (`Brain communications`, `Current biology : CB`) are capitalised the way APA writes them (`Brain Communications`, `Current Biology: CB`); names that already have capitals, or capitals inside a word (`PLoS ONE`, `eLife`), are left alone. An issue is never written without a volume. |
| Preprint | `Author. (Year). Title. *Server*. https://doi.org/...` |
| Book, data set, thesis, report | The title is italic and comes first after the date: `Author. (Year). *Title* [Data set]. Publisher. DOI` (`[Data set]` and `[Thesis]` are added for those two). The "publisher" is the venue the source gave, such as Zenodo. |
| Book chapter, conference paper, reference entry | `Author. (Year). Title. In *Book or proceedings* (pp. 10–20). DOI` Editors, the publisher and the place are not collected. |
| Wikipedia | `Title. (n.d.). In *Wikipedia*. Retrieved October 14, 2026, from URL`. The retrieval date is the day you export, because Wikipedia changes. |
| Link | The DOI as an `https://doi.org/` address (DOIs are stored in lower case, which is how DOI addresses work), else the page address, never a database record such as an openalex.org page. **No full stop after a link.** With neither, the reference ends in a full stop and says so. |
| The list | Alphabetical by the first author's family name, **letter by letter** (capitals, accents, spaces and punctuation ignored); a single author before several that start with the same author; then by year, earliest first, with undated works first; a work with no author is placed by the first word of its title (ignoring A, An, The). |

**What can be wrong, and what the app tells you.** (In-text citations are in the next section.) Under each saved reference the panel lists the things to check, for example: the author names came as one piece of text (OpenAlex gives `Robert Stickgold` rather than family and given names), so they were split by rule; no volume, issue or pages were found; the title looks like Title Case; no year, no author or no DOI was found; a chapter lacks its editors and publisher; a Wikipedia reference uses today's date. The sources give volume, issue and pages unevenly: OpenAlex (`biblio`), Crossref, PubMed, Europe PMC and DOAJ do for many articles; DataCite, Zenodo, Semantic Scholar and Wikipedia do not at all. **Metadata can be incomplete, so check every reference before you submit.**

**How the rules were checked.** The author limits (including `. . .` for twenty-one or more) and the `Article` number form were checked on 2026-10-14 against several university library guides that follow the 7th edition of the APA manual. APA's own style pages could not be read by the tool used, and the manual itself was not consulted, so these rules are as good as those guides. The preprint, data set, thesis and Wikipedia forms follow the same guides' examples less closely and are the most likely to need a manual fix.

## In-text citations (APA 7)

The **In-text citations** button, beside Settings and Saved list under the search box, opens a panel with the in-text citation for every saved source, ready to copy: **in brackets** (`(Stickgold, 2005)`, for the end of a sentence) and **in a sentence** (`Stickgold (2005)`, when the author is part of it), each with its own Copy button, and one button that copies every bracketed citation, one per line. They are worked out together with the reference list (same order, same letters), and the copy keeps italics where a title is italic. The rules, from `packages/core/src/apa.ts`:

| Case | Citation |
| --- | --- |
| One author | `(Stickgold, 2005)` and `Stickgold (2005)` |
| Two authors | `(Stickgold & Walker, 2005)` in brackets, `Stickgold and Walker (2005)` in a sentence |
| Three or more | `(Smith et al., 2020)`: the first author and *et al.*, at every citation, including the first |
| Group author | The name as it is: `(World Health Organization, 2020)`. Abbreviating it after its first use is left to you |
| No year | `(Smith, n.d.)` |
| Same authors, same year | The same letters as the reference list: `(Smith, 2020a)`, `(Smith, 2020b)`; with no year `(Smith, n.d.-a)` |
| First authors with the same surname but different initials | The first author's initials in every citation: `(J. Smith & Lee, 2020)`, `(K. Smith, 2019)`. If the initials are also the same, the ordinary form is used |
| Works that would shorten to the same *et al.* citation (the same first author or authors and the same year) | As many authors as it takes to tell them apart, then *et al.*: `(Smith, Jones, Lee, et al., 2020)` and `(Smith, Jones, Park, et al., 2020)` |
| No author | The title stands in for the author: in quotation marks for an article, chapter or web page, `(“Sleep and Memory,” 2020)` and `“Sleep and Memory” (2020)`; in italics for a book, report, data set or thesis. The comma goes inside the quotation marks, and a title ending in `?` keeps it with no comma: `(“Why Do We Sleep?” 2017)` |

**Titles in a citation** are shortened to what comes before a colon, at most six words, never ending on a small word such as *of* or *the*, and written in title case (main words capitalised; words with capitals inside, such as `COVID-19`, are kept). This differs from the reference list, which wants sentence case.

**What is not done:** page numbers (add them after the year for a quotation: `(Smith, 2020, p. 5)`), several sources in one pair of brackets (put them in alphabetical order with semicolons: `(Jones, 2019; Smith, 2020)`, and give an author once for several works: `(Smith, 2019, 2020)`), abbreviations for group authors, and secondary sources ("as cited in"). The panel says so. As with the references, the citations are only as good as the author names the sources gave (see "References (APA 7)"), and the same checks apply.

**How the rules were checked.** On 2026-10-14, against several university library guides that follow the 7th edition (the same limitation as for the references: not against the manual itself). The guides agree on all the rules above. They disagree about one point, how a title standing in for an author is capitalised in the text: one guide says sentence case, but its own example, and the others, use title case, which is what is done here, so that case is the one most likely to need a manual change.

## The search protocol

**Download search protocol (JSON)** (under "Search elsewhere") saves a record of the search on the page so that it can be written up and repeated. The file is built only from named fields, so nothing else can enter it, and it has a `schema` name and a `schemaVersion`. It records:

- the app version and the date and time;
- the sources that were asked and how many results each was asked for;
- the query as typed and **how it was read**: every concept with its variants (and which came from the curated thesaurus, with the kind of entry and its note), the common words left out, the generic words set aside, whether it was searched exactly as typed; **the exact text each source received** and what it could not apply, how each source answered (ok with a count, rate-limited, failed or skipped, with the message), the fallback passes if any ran (the concept each dropped, what each source received, how each answered), and how many records were fetched, how many works remained after merging duplicates, how many are in the main list, how many are set apart as partial matches, as other languages and as other types, and how many your filters hide;
- the counterargument search too, if one was run: its mode, its terms, and the same details;
- the filters, every factor's switch and weight, the results layout (preferred languages, whether non-article types are in the main list, and the 15-result threshold), the recency half-life, the preferred levels, the year ages were measured from, and the relevance method (BM25 and its two parameters);
- the title, DOI and link of each source on your saved list.

It contains **no API key and no contact email**, and no abstracts or result lists. Sources update their data and rate limits change, so a repeated search can give different results; the file says so. It lets a reader see exactly what was asked and how, not receive the same answers.

## Access: open access, PDFs and library links

Every card carries an **access badge** in plain text: "Open access (gold)" (or green, hybrid, bronze, diamond), "Not open access, try UBC Library", or "Open access status unknown, try UBC Library" when the provider does not say. The words "try UBC Library" appear only on cards that actually have a library button. A result is never hidden or ranked lower for not being open access: the factor's default weight is 0, and only the "Open access only" filter, which you have to switch on, hides closed results.

Each card can show up to three buttons, in this order:

1. **Open access PDF.** Shown only when OpenAlex names a direct PDF for a copy that OpenAlex itself marks as open access (its `best_oa_location`). It is never taken from a paywalled copy, and a green or repository copy without a PDF link gets no button. This is OpenAlex's own data for now. Unpaywall, the dedicated open-access lookup, is planned for a later stage and will feed the same button.
2. **Access with UBC Library.** Shown on every result that has a landing-page address or a DOI, whether or not it is open access, as long as `libraryProxyPrefix` in `config.js` is not empty. Next to it: "Access depends on UBC Library subscriptions; you may be asked to log in." The button only builds a link to your library's login: Sourcly never sees your password or your library account (Settings says so beside the library name and sign-in prefix, which are set in `config.js`).
3. **DOI.** The plain `https://doi.org/...` link.

### How the library link is built

The link is `libraryProxyPrefix` (in `config.js`) followed by the address to open, **percent-encoded as a single value**. The address is the publisher's **landing page** when the result has one, and the `https://doi.org/<DOI>` link only as a fallback. (A provider's own record page, such as an openalex.org page, does not count as a landing page, because a library cannot open it for you.) Percent-encoding is how any web address is passed inside a link's query string, and it keeps characters such as `&`, `?` and `#` inside the address from being read as part of the link.

The default prefix is UBC Library's OpenAthens redirector, `https://go.openathens.net/redirector/ubc.ca?url=`. A finished link looks like this:

```
https://go.openathens.net/redirector/ubc.ca?url=https%3A%2F%2Fdoi.org%2F10.1038%2Fnature04286
```

**What was checked** (2026-10-14):

- **A manual test** confirmed that the prefix works with both a publisher landing page and a doi.org link, with the address percent-encoded, for a ScienceDirect book chapter.
- **UBC Library's current guide** (guides.library.ubc.ca/connect, updated July 2026) gives this prefix and says OpenAthens replaced EZproxy in June 2021. Its own example appends the address raw, and it says adding the prefix to a DOI is "not recommended".
- **The redirector itself**, tested with plain requests that sent a browser-like User-Agent and no sign-in: ScienceDirect, Elsevier and Nature links, both landing pages and DOI links, were all forwarded to the publisher's sign-in for UBC, whether the address was raw or encoded. (Some earlier test requests that did not look like a browser, or that came in quick bursts, got an empty or "Please wait" response instead, so quick scripted tests of this redirector are not a reliable guide. A real browser is.) Sourcly sends the address encoded because that is the standard way to put one web address inside another link, it is what the maintainer confirmed works, and it stops `&`, `?` and `#` inside the address from being read as part of the link. The landing page comes first because that is the form UBC's guide shows, with the encoded DOI link as the fallback.

**The legacy EZproxy prefix no longer works for most resources.** UBC Library replaced EZproxy with OpenAthens in June 2021 and says "a few UBC Library e-resources still require EZproxy" (its guide names three: eNCPT, Patrologiae Graecae and Torrossa). So `https://login.ezproxy.library.ubc.ca/login?url=` is not the default. A library that still uses EZproxy should end its prefix in `qurl=` instead of `url=`: OCLC, who make EZproxy, document that an encoded address needs `qurl=`, and an encoded address after `url=` leaves users on the EZproxy menu page.

Which prefix suits your library is a setting. Change `libraryProxyPrefix` in `config.js`, or leave it empty to hide the button.

## Search elsewhere

Under the results is a row of links that run the same query on other search engines, each opening in a new tab: Google Scholar, Google, DuckDuckGo and UBC Library's search. They are plain links. Sourcly sends nothing to those sites, and the text you typed is passed as it is, encoded.

**The UBC Library link.** UBC Library's official guides publish no search-link pattern (they explain only how to copy permanent links to single items), so the address was taken from UBC's own search box. On search.library.ubc.ca the "everything" search is a plain GET form that submits to `https://ubc.summon.serialssolutions.com/search` with the query in the `s.q` parameter. Opening `https://ubc.summon.serialssolutions.com/search?s.q=sleep%20memory%20consolidation` in a browser ran that search ("Results for sleep memory consolidation"). The tempting `https://search.library.ubc.ca/?q=...` does **not** run a search. Because this is observed behaviour rather than a documented one, it is a setting: `librarySearchUrl` in `config.js` (the address up to and including `s.q=`). Leave it empty to hide the link.

Sourcly does not search the open web itself. Websites, news and blogs are outside what the academic sources index, which is what the links above are for.

## The single-file build

`pnpm build` makes `apps/web/dist/index.html`: the app's scripts and styles are inlined into that one file (by `vite-plugin-singlefile`), so it works when you double-click it, with no server. Next to it is `config.js`, a plain classic script that is **not** bundled, so the site name, footer, repository links, library prefix and contact email can be changed by editing a text file, with no rebuild. `pnpm check:dist` (also run by CI and by the release workflow) fails if `index.html` would load any other file, so the promise cannot quietly break.

**What was checked from a folder** (2026-10-14, Chrome, a fresh profile, the page opened as `file://...`; a page opened this way has the origin `null`, which is why each source was also checked with `Origin: null`):

- the page loads, `config.js` is read, and editing it in an unzipped release changes the title and footer on reload;
- a real search reached every source that allows browser requests (OpenAlex, Crossref, PubMed, Europe PMC, DOAJ, DataCite, Zenodo and Wikipedia answered; Semantic Scholar answered some requests and refused others with HTTP 429, without the header a browser needs to read that, which the page reports as "no readable answer");
- a counterargument search, saving to the list (`localStorage` works), copying and downloading references, and downloading the search protocol all worked.

**What was not checked:** other browsers. Chrome, Firefox and Safari treat pages opened from files differently (storage, the clipboard and downloads in particular), so if something fails when you double-click the file, serve the folder instead (`npx serve`) and the hosted site behaves identically. The Docker and Railway files were written but **not run**: Docker was not running on the machine they were written on.

**Hosting.** The built site is static. The `Dockerfile` builds it and serves it with nginx (`deploy/nginx.conf.template`, listening on the `PORT` that Railway sets), and `railway.toml` points Railway at that Dockerfile. `index.html` and `config.js` are sent with `Cache-Control: no-cache`, so edits and new versions show at once; the server adds `Referrer-Policy: no-referrer` and `X-Content-Type-Options: nosniff`. It holds no secrets and runs none of Sourcly's code.

**Releases.** Pushing a tag such as `v0.2.0` runs `.github/workflows/release.yml`: install, typecheck, test, build, `check:dist`, a check that the tag equals the version, then `sourcly-0.2.0.zip` (`index.html`, `config.js`, a short README and the licence) is attached to a GitHub Release. The version is written once, as `version` in the root `package.json` (`pnpm version:set` changes it and `CITATION.cff` together), and the footer shows it as, for example, `v0.1.0`; it is also recorded in the search protocol. The footer's "Download" link points at `releases/latest`. The workflow's steps were run by hand on this machine (the zip was built, unzipped and opened from a folder), but the workflow itself has not run on GitHub yet.

## The benchmark

`pnpm eval:search` runs the queries of `apps/web/eval/benchmark.json` (plus two lookups) against the **live** sources and prints what the page would show, so changes to the thesaurus, the word lists or the query building can be judged on real answers instead of by eye. It needs the network and is **not** part of `pnpm test` or the continuous-integration run (it is a Vitest run with its own config, `apps/web/vitest.eval.config.ts`, so it adds no dependency). It uses the same code as the page (providers, query writing, matching, ranking, sections, fallback passes, typo help and suggested terms), without a contact email, so Unpaywall is not asked.

The twelve queries are "How AI understand odor", "machine learning odor prediction", "caos double pendulum", "chaos double pendulum", "CAN bus protocol", "climate change impact on coral reefs", "CRISPR off-target effects prediction", "microplastics effects on marine fish", "attention mechanism in transformers explained", "intermittent fasting and cognitive performance", "perovskite solar cell stability" and "how do vaccines train the immune system".

**What it prints, per query:** the sources asked and how many results each gave; the concepts and their variants; the exact query each source received; whether a fallback ran, the counts it used and what each pass sent; the number of results in each section; the top 15 (title, year, venue, sources, the concepts matched with the variant and field, "Matches N of M concepts", section, language); the typo suggestion; the suggested terms; and, for each paper in `mustInclude`, whether it was found and its rank and section. The same text is written to `apps/web/eval/output/<query>.md` (not committed).

**`mustInclude`** lists papers a good search for that query should find, as DOIs. Each DOI was checked (Crossref, or DataCite for an arXiv paper) to resolve to the title written next to it. They only measure the search: **nothing in the ranking code mentions any query, DOI or topic**, and no paper is boosted or special-cased.

**Checks** printed at the end (PASS, FAIL, or SKIP when OpenAlex's budget ran out and the answer cannot be judged):

- no paper in the top 10 of an odor query is a food or flavour chemistry paper without a machine-learning term;
- the `mustInclude` papers of the odor queries are in the top 30 of the main list;
- every result in the main list of the pendulum queries is about a double pendulum, and "caos double pendulum" offers "Did you mean: chaos ...";
- the top 15 of "CAN bus protocol" are about CAN (capitals) or the controller area network, not the verb "can";
- no result in another language is in the main list of the English queries;
- the DOI `10.1016/B978-0-323-99796-6.00014-X` and the address `https://www.nature.com/articles/s42004-024-01373-2` resolve to the right works.

**Quota.** Without a key OpenAlex shares a small daily budget (the response says it is shared with everyone on the same network address), and answers HTTP 429 when it is used up. A 429 can also be OpenAlex's one-request-per-second limit on queries with more than 5 Boolean operators (see "Provider notes"): the search waits the second it asks for and asks again, and the end of the output says how many times that happened. Only a 429 without a short retry hint is reported as a used-up budget; the checks that cannot be judged without OpenAlex then print SKIP instead of FAIL, and the output says so, never hiding it. Answers are kept on disk for a day in `apps/web/eval/.cache/` (not committed), so a run that was cut short carries on where it stopped and running it again while changing the code costs nothing; `EVAL_REFRESH=1 pnpm eval:search` asks the sources again. An optional `OPENALEX_API_KEY` in the environment is sent to OpenAlex like the key field in Settings and is never written to the cache or to the output. A change to the thesaurus or to the way a query is written changes the text a source receives, so the sources are asked again for the queries it touches (OpenAlex's budget is about 100 searches a day without a key, and a search that fills two pages uses two).

**Last full run (2026-10-15, OpenAlex, Crossref, PubMed and Europe PMC all answering): 24 of 29 checks pass, none skipped.** What does not, and why:

- *"How AI understand odor", the three `mustInclude` papers* (checked: in the main list at #67, #131 and #164, so all three are fetched, but none is in the top 30). The main list holds 334 results that match both concepts. The order is the coverage tier, then phrase match, then the score, and the score favours a result that has both concepts in its **title**. These three have "odor" in the title and the machine-learning words only in the abstract (`neural network`, `machine learning`), so 66 results rank above the first one, most of them with both concepts in the title. Changing the weights does not fix it without moving others up too: with the citation weight at 3 the first paper reaches #30, the others #52 and #152; with the abstract weight at 1 the three are at #31, #80 and #97 (probed on the same fetched results, not applied). The same three papers pass for "machine learning odor prediction" (#28, #29 and #5), where the word "prediction" is a third concept they all contain; the first two are only a rank or two inside the limit.
- *"caos double pendulum" shows no "Did you mean: chaos"*: the strict pass finds one result that has both words, the fallback does start, but the 20 results of Crossref (which cannot require every word) are enough to make 15 results that match all but one concept, and that stops the passes before the first one (see "Fallback passes"), so too few results contain "chaos" for the typo help (at least 5, and twice as many as "caos") to speak. The main list is still all about double pendulums.
- *"attention mechanism in transformers explained", "Attention Is All You Need" (`mustInclude`)*: not among the 200 results OpenAlex returned, nor in the other sources' 100: the query matches tens of thousands of works and OpenAlex keeps 200.

Two things were found by this run and changed: the `odor` entry no longer carries the bare word `smell` (13 of the first 70 results of "How AI understand odor" were about code smells, and so were 4 of the first 8 of "machine learning odor prediction"; the phrase `sense of smell` stays), and OpenAlex's one-request-per-second limit on broad Boolean queries is now waited out (see "Provider notes"). Two sources also answered "could not be read" for one search in the middle of a run; asking again worked.

## Provider notes

Unpaywall (used only by a lookup, never searched): `https://api.unpaywall.org/v2/<doi>?email=<address>`. It needs an email address with every request (without one: HTTP 422, checked 2026-10-15), sends `access-control-allow-origin: *`, and asks for no more than 100,000 calls a day. Sourcly sends the contact email from `config.js` and asks only when one is set; the response's `best_oa_location.url_for_pdf` becomes the open-access PDF link, and only when `is_oa` is true.

### OpenAlex

- Queried at `https://api.openalex.org/works` with `search.title_and_abstract`, `per_page` (at most 100), `page` and `select` (to fetch only the fields Sourcly uses). At 100 results per source a second page is fetched (up to 200 works), one request after the other, and only when the first page was full. The number of works that match a concept alone (for the fallback order) comes from a `per_page=1&select=id` request, whose `meta.count` is the total. It allows requests from any website, so it works directly from the browser.
- **No API key is needed.** OpenAlex's current documentation says basic use needs no key. Without a key the daily free allowance is small: the response headers showed a budget of $0.10 per day, and a search costs $0.001, so roughly 100 searches per day (a two-page search and its concept counts use several). The response says the budget is shared with everyone on the same network address, so people on a shared network (for example campus Wi-Fi) may use it up sooner (the headers showed 6 requests left on 2026-10-15). When it runs out OpenAlex answers HTTP 429, and Sourcly shows the provider as "rate-limited" and keeps working with the others.
- **An optional personal key** (free, from an OpenAlex account at openalex.org/settings/api) raises that allowance; OpenAlex's documentation says about tenfold. You can paste one into Settings. It is sent only to OpenAlex, as OpenAlex's documented `api_key` parameter. It is stored only in your own browser (localStorage), never in the code, in `config.js`, in the page address or in an export, and "Remove key" erases it. If OpenAlex rejects a key (HTTP 401) the whole search fails with that message instead of falling back to keyless use, so Sourcly says so and tells you to check or remove the key. Anyone who can use your browser profile can read a stored key, so use a personal key, not a shared one.
- **A second limit: one request per second for broad Boolean queries.** A query with more than 5 Boolean operators (`OR`, `AND`, `NOT`) is limited to one request per second per client (5 per second with a key); OpenAlex answers the next one with HTTP 429, `Retry-After: 1` and the message "Your query uses 10 boolean operators... Please wait 1s and retry" (checked 2026-10-15; the response body has `"reason":"broad_boolean_query"`). Every search with synonyms is such a query ("AI" and "odor" is 10 operators), and the second page of a search is asked for right after the first (and the eval's next query right after the last one), so without a wait a search could fail with "rate-limited" while the daily budget was not used up (seen in the eval; not reproduced in a browser). Sourcly now waits the seconds `Retry-After` asks for, plus a tenth of a second, and asks again, at most twice, and only when the wait is 5 seconds or less; a longer wait, or none, is a spent daily budget and is reported as before. The same wait is used by the counts that order the fallback passes. A search that is cancelled stops waiting at once.
- The `mailto` "polite pool" parameter is not mentioned in OpenAlex's current documentation and had no effect on the rate-limit headers when tested, so Sourcly does not send it.
- Sourcly sends `search.title_and_abstract`, which OpenAlex documents as "title and abstract text only", not the plain `search` parameter, which also reads the full text and keywords (see "Writing a search" for the measurements). A work whose only match is in its full text, or in the keywords OpenAlex assigns to it, is not returned. A single work is fetched at `works/doi:<doi>`, `works/pmid:<pmid>` or `works/W<id>`; `works/pmcid:` is not supported (HTTP 404), so PubMed Central IDs go through Europe PMC. Its `related_works` list gives the related papers, and the filters `cited_by:W...` and `cites:W...` give the references and the citing works (checked 2026-10-15). OpenAlex decides which 100 results come back. Sourcly then ranks those with its own BM25, but it only ever sees what OpenAlex chose to return, and OpenAlex's own relevance score includes a weighting for citation counts, so the candidate set already leans towards well-cited work.
- OpenAlex stores abstracts as a word-to-position index. Sourcly rebuilds the text from it.
- Author countries are collected from the authors' institutions, and the work's language is OpenAlex's automatic detection. Both are stored for a future bias-analysis panel.
- The retraction flag comes from OpenAlex's `is_retracted`, which it takes from the Retraction Watch database.
- Volume, issue and pages come from `biblio` (`volume`, `issue`, `first_page`, `last_page`), joined as a page range.

### Crossref

- Queried at `https://api.crossref.org/works` with `query.bibliographic`, `rows` and `select`. It sends `access-control-allow-origin: *` and needs no key. `rows` is asked for at most 20 (the service allows 1000), and only for journal articles, conference papers, preprints, book chapters, books and monographs. Crossref cannot require every word, so its order is loose: in the chaos test, 24 of the 27 results among the first 100 that had all three words were already among the first 50, so the other 50 added little but noise. For a broad topic the cap does cost results (in the sleep test, 45 of the 95 matching results in the first 100 were in the first 50), and plenty come from the other sources. Crossref is only a supplement: its results pass the same local concept matching as everyone's, and those that do not match go to "Partial matches". The cap and the type filter are in the Crossref provider, and "How we searched" says what is asked for. A single work is fetched at `works/<doi>`.
- The public pool has no sign-up and a small allowance: Crossref's documentation gives 5 requests with one at a time, and its response headers showed 1 per second. If `contactEmail` is set in `config.js` it is sent as `mailto`, which moves requests to Crossref's faster polite pool.
- `select` accepts only the names Crossref lists, and `language` and `subtype` are not among them. So Crossref results have no language, and every `posted-content` record is treated as a preprint.
- Types: journal-article is a journal article; posted-content a preprint; proceedings-article a conference paper; the book, chapter, reference-entry, dissertation, report and dataset types map to their obvious kind; Crossref's own "other" is unknown. A record whose `update-to` names a retraction or withdrawal of a *different* work is a retraction notice, not research (type "other"). Publishers' "RETRACTED ARTICLE: ..." records list a retraction `update-to` that points at the article's own DOI (checked 2026-10-14); those are the research article itself, flagged retracted through `updated-by`.
- A work is flagged retracted when its `updated-by` list has a `retraction` or `withdrawal` entry (these come from Retraction Watch and from publishers). A work with no such entry is shown as "unknown", not "not retracted", because Crossref only lists what it knows of.
- Abstracts are JATS XML and are converted to plain text. Most records have none.
- Volume, issue and pages come from `volume`, `issue` and `page` (the page range, or an article number such as `e0173456`), with `article-number` as a fallback. All four are valid `select` names. Many records have none (checked: the early *Sleep* journal DOIs have no volume or pages in Crossref).

### PubMed

- Two requests per search. `esearch.fcgi` (JSON) returns PubMed IDs in relevance order, then `efetch.fcgi` returns the records as XML, which Sourcly reads with its own small XML reader. Both send `access-control-allow-origin: *`. Without a key NCBI allows 3 requests per second. Sourcly sends NCBI's `tool` parameter, and `email` too if `contactEmail` is set.
- At most 100 results. Every word and phrase is sent with the `[tiab]` (title/abstract) tag, which turns off PubMed's automatic term matching (see "Writing a search"). `[tiab]` replaced `[tw]` because `[tw]` also searches MeSH headings, which Sourcly does not count as a match. A consequence is that nothing is expanded for you except by the thesaurus: `memory` does not find `memories` in PubMed itself (the plural is only folded when results are checked here), and a heading PubMed would have mapped `heart attack` to (`Myocardial Infarction`) is found only if the record also uses your words. "Search exactly as typed" gives the broader matching back.
- Types come from PubMed's publication types: Review, Systematic Review and Meta-Analysis are reviews; Preprint a preprint; Journal Article a journal article; Editorial, Letter, Comment and similar are "other". PubMed has no citation counts.
- Retraction comes from the "Retracted Publication" type or a "RetractionIn" correction link. A record with neither is shown as "not retracted".
- A PubMed Central copy is free to read, and the card links to it. PubMed says nothing about licences, so the open-access kind stays unknown.
- Volume, issue and pages come from `JournalIssue/Volume`, `JournalIssue/Issue` and `Pagination/MedlinePgn`. Journal names are in NLM's lower-case style, which the APA formatter capitalises.

### Europe PMC

- `https://www.ebi.ac.uk/europepmc/webservices/rest/search` with `resultType=core`. Every word and phrase is sent as `TITLE_ABS:` (title and abstract only), because unfielded searches read the full text of open-access papers. It sends `access-control-allow-origin: *` and needs no key; 100 results are asked for (it accepted 200).
- It covers PubMed records, PubMed Central, preprints (source `PPR`), theses, books and patents. Preprints and "Retracted Publication" are read from the record's own type list. The citation count is Europe PMC's `citedByCount`.
- A free copy is found from the record's full-text links (marked Free or Open access), with its PDF when it has one.
- Volume, issue and pages come from `journalInfo.volume`, `journalInfo.issue` and `pageInfo` (which can be an article number such as `RP104862`).

### DOAJ

- `https://doaj.org/api/search/articles/<query>`, 100 results at most, no key, `access-control-allow-origin: *`. DOAJ documents a limit of two requests per second.
- DOAJ lists only journals that are fully open access, so every result is open access and is labelled a journal article, which the label shows came from "search/articles". It gives no citation counts.
- Volume, issue and pages come from `bibjson.journal.volume`, `bibjson.journal.number` (DOAJ's name for the issue) and `bibjson.start_page` / `end_page`.

### DataCite

- `https://api.datacite.org/dois` with `page[size]` (100 at most; 1000 returned an 18 MB response). No key; it echoes the requesting origin in `access-control-allow-origin`.
- DataCite holds deposits in repositories (datasets, theses, preprints and articles in institutional repositories), not publishers' journals, so the venue kind is "repository" unless the record says otherwise. Types follow `resourceTypeGeneral`. Open access is claimed only when the rights list says so (a Creative Commons licence or "open access"), never otherwise.

### Zenodo

- `https://zenodo.org/api/records`, no token, `access-control-allow-origin: *`. An anonymous request may ask for **at most 25** results, and Zenodo limits search to 30 requests per minute.
- Zenodo holds whatever people upload, so many results are datasets or software (labelled "other"); a publication's subtype decides its type. The same paper can be there as a copy: a real example is the Nature paper deposited under its own DOI, which merges with OpenAlex's record.

### Wikipedia

- The English MediaWiki API (CirrusSearch), one request that searches and returns each page's introduction. A group of alternatives inside a larger search is ignored by Wikipedia, so Sourcly leaves it out and says so. A browser can read the answer only because the request carries `origin=*`, MediaWiki's documented switch for anonymous cross-origin requests. It returns intro text for at most 20 pages per request; Sourcly asks for **5**, because Wikipedia is an example of a tertiary source and not a place to find papers.
- Pages are labelled as encyclopedia entries (tertiary) and not peer-reviewed. They have no authors, year or citation count, and are free to read.

### Semantic Scholar (keyless)

- `https://api.semanticscholar.org/graph/v1/paper/search`, no key, 100 results at most. Keyless users share one pool of requests, and in practice that pool answered HTTP 429 to every request while this was built. Such an answer carries no CORS header, so the browser cannot read it and the page reports "gave no readable answer"; the browser's developer console also logs a CORS error. Both are expected.
- **Least verified of the nine.** The result shape follows Semantic Scholar's official OpenAPI specification, and the test data is hand-written from it, not recorded. On 2026-10-14 it did answer some requests (100 records were read, in the app and from a downloaded folder) between the HTTP 429 refusals, but those answers were not compared with Semantic Scholar's own site, so its mapping has not been checked against real records the way the other eight were. It gives no volume, issue or pages in this app. A hyphen in your search is sent as a space, because its API specification says hyphenated terms find nothing (also not confirmed live).
- The AI-written "tldr" summary is deliberately never requested.

### arXiv (skipped)

arXiv is listed in Settings as not available, and every search reports it as skipped. Its search API sends no CORS headers (checked from a web origin and from `file://`), and its manual says "The API is not intended to be used inside a web browser by itself". A browser therefore cannot read its answers, and Sourcly has no server to relay them. OpenAlex indexes many arXiv preprints.

## Known limitations

- **Citation counts favour older and English-language, Western work.** Dividing by age helps with the first, but not the others. A low count often means "newer", "from a smaller research community" or "not in English", not "worse". Citation counts are also not quality: a paper can be cited often because it is wrong.
- **Labels are heuristics based on metadata.** They describe the kind of document, not the author's relationship to the material, which is what actually decides whether a source is primary, secondary or tertiary for your purpose. Always check.
- **Metadata can be wrong.** For example, OpenAlex lists one encyclopedia entry under a source it calls a "journal", and its type assignments were recently re-run for about 10% of all works. Sourcly labels what the metadata says.
- **Blogs, news, interviews and most grey literature are not indexed** by the academic APIs Sourcly uses, so they will not appear. That is a limit of the data, not a judgment that they are unreliable.
- **Providers cover different things.** A result missing from one provider may exist in another. Results are only as complete as the providers selected.
- **Allowances are limited**, and sources can change their rules. OpenAlex's keyless allowance is about 100 searches a day; Zenodo allows 30 searches a minute; PubMed 3 requests a second; DOAJ 2. The app reports a refusal as a status rather than hiding it.
- **Sources return different amounts.** Crossref is asked for at most 20 results, Zenodo returns at most 25 and Wikipedia 5, so they can never fill a page of results the way OpenAlex can.
- **Several sources return deposits, not papers.** DataCite and Zenodo mostly return datasets, software and repository copies, and anyone can upload to them. They are off by default; when on, what only they hold goes to the collapsed "Datasets, presentations and other types" section, never hidden.
- **Merging is a heuristic.** Spelling variants, translated titles and records with no author can be missed, so the same work may appear twice. Two different DOIs are never merged, so a preprint and its published version appear separately.
- **Missing numbers count as neutral.** PubMed, DOAJ, Zenodo and Wikipedia give no citation counts, so for those results the citations factor scores 0.5 rather than 0; that can lift a result with no count above one with a low count.
- **Semantic Scholar and arXiv are limited** as described under Provider notes: the first because of its shared free pool, the second because browsers cannot read it.
- **Non-academic sources are not searched.** The "Search elsewhere" links are the way to reach them.
- **The library button is a shortcut, not a guarantee.** Whether it opens a result depends on your library's subscriptions, on which link style your library currently supports, and on the publisher. You may be asked to log in, and some resources will not open through it.
- **The counterarguments panel is keyword-based.** It finds sources whose title or abstract contains words such as *limitation*, *criticism* or *bias*. It cannot tell whether a source actually disagrees with a claim, only that it uses those words, and the words are ambiguous: *bias* is also a statistical term, *challenge* a kind of trial, *fail* appears in "no evidence of failure", and "no evidence of harm" supports a claim rather than opposing it. A source can disagree without any of the words, and a source that uses them can agree. Read before citing.
- **The counterarguments panel reads less than a source matched.** It marks and counts terms in the title and abstract only, while a source may have matched them in the full text (OpenAlex and Europe PMC search full text), so some results show no marked term, and results with no abstract have little to match. Crossref and Semantic Scholar cannot narrow by terms, so their results are ranked by the terms they happen to contain.
- **Notices are recognised by their titles.** A retraction or correction notice whose title does not start in one of the usual ways is missed, and an unusual research title that does (for example one beginning `Retraction Watch:`) is mistaken for a notice. Review badges are only as good as the source's own type. A second search also uses up a second round of every source's allowance.
- **Relevance only sees what the sources returned.** Each source sends back its own top 100 (or fewer), chosen by its own ranking, and BM25 re-orders only those. A strong match that no source ranked highly is never seen, and the candidate set carries each source's biases (OpenAlex's weighting towards citations, for one).
- **BM25 reads only the title, abstract and author keywords.** A result with no abstract (common for Crossref and DataCite records) has less text to match, so it can score lower than an equally relevant result that has one. Author keywords come from only some sources, which also changes how long a result's text is. Stopwords and the plural rule are for English only, so a non-English title is matched on its words as written.
- **Search is lexical, not semantic.** Sourcly matches words and phrases; it does not know what they mean. A result that contains `chaos` and `double pendulum` in unrelated places is in tier 1 just like one about the double pendulum; the phrase match softens this but cannot remove it. **Synonyms exist only where the curated thesaurus or the paper's own wording provides them**: `odor` finds `olfaction` because the thesaurus says so, but `scent perception` is another phrase, `chaotic` is not `chaos`, and `selforganizing`, `self-organizing` and `self organizing` are three different spellings (the hyphenated form needs its words adjacent, so it also matches `self organizing`, but not `selforganizing`). The thesaurus is short and mostly science and engineering; a field it does not cover gets no alternatives. Only the title, author keywords and abstract are read, so a record without an abstract can fall into a lower tier although its full text matches. The matching words are English-only, like the normalizer. A misspelt word can pull in results that contain it by chance; correcting the spelling removes them, and the card says what each result matched and what it did not.
- **Ambiguous words and abbreviations can pull in unrelated results.** `AI` is matched with its capitals, so "Ai Weiwei" is not a match, but a thesaurus variant such as `neural network` is also a biology term, `CAN` has other meanings than the controller area network, and `machine learning` in a paper about something else still matches the concept `AI`. The card shows which variant matched and where, so you can see when that happened. Generic words are set aside by a fixed list; a word on the list that matters to your topic ("effect" in a paper about side effects, say) is not required, and "Search exactly as typed" turns the list off.
- **Provider coverage differs.** OpenAlex has the most works, PubMed and Europe PMC only life sciences, Crossref few abstracts; a concept a source cannot take alternatives for (Crossref, Semantic Scholar) is sent as the typed word only and checked locally afterwards, so those sources find fewer of the papers that use another word.
- **Language detection is a heuristic.** It reads the title and the start of the abstract with small word lists and letter marks for nine Latin-script languages and by script for the rest (see "Language detection"). Short titles often give too little to go on, so the source's word is used, and Crossref and Semantic Scholar give none, so many results are "unknown"; unknown results stay in the main list. A language outside the list can be named wrongly or not at all. Where the text and a source disagree the result is "Language unclear" and is placed by the text, which can be wrong too (an English abstract with a Portuguese title, say). The "Other languages" section exists so that a wrong call costs one click, never a lost result.
- **The fallback passes widen by dropping a concept, which can bring in off-topic work.** They run only when fewer than 15 results match every concept, are limited to three, and what they find is labelled "Matches N of M concepts"; which concept goes first is judged from OpenAlex's counts, and from the order typed when OpenAlex is off or refuses (for example when its keyless daily budget is used up). A concept's count says how common it is, not how important it is to you.
- **Spelling help is limited.** "Did you mean ...?" is worked out from the results that came back, so it needs enough results to judge from, cannot suggest a word that no result contains, does not flag a typo that is itself a common word in the results, and can mistake a rare correct word for a slip. It never corrects anything by itself; a wrong suggestion costs a click.
- **Relevance is relative to the set.** The best result is always 1, so a 1 means "best of these", not "a good match". Scores shift as sources answer or the set changes. BM25 does not enforce phrases, `OR` or `NOT`: it counts words.
- **Provider agreement is not accuracy.** Sources overlap heavily (Europe PMC includes PubMed records, and several draw on Crossref and DataCite metadata), so agreement can mean "shared a data source" rather than "independently found". Coverage also differs: a biomedical paper can be returned by more sources than an equally good humanities paper, and work in a repository only Zenodo or DOAJ holds can never score high. That is why the default weight is small.
- **A reduced question loses its meaning.** Removing common and generic words keeps the topic words and drops the grammar, so "does sleep help or hurt memory" and "sleep memory help hurt" search nearly the same concepts. Negation in plain sentences ("without", "except") is not understood; use `NOT`. Write the key concepts as nouns instead of a question (see the README's "How to write a good search").
- **Suggested terms come from the top 30 results of the main list**, only from author keywords and MeSH headings found in at least three of them, so they repeat the ranking's biases and favour biomedicine (MeSH) and fields where authors give keywords. They are suggestions, not a map of the field, and nothing is shown when fewer than three terms qualify.
- **Not every source understands every operator, and not every source can require every word.** Crossref and Semantic Scholar receive only the words, so a `NOT`, `OR` or phrase is not applied there, and Crossref in particular returns many results that contain only some of the words (the panel says so, and term coverage sets them apart afterwards). Wikipedia ignores a group of alternatives inside a larger search.
- **Strict searching has costs, and the candidate pool is small.** PubMed and Europe PMC are asked for exact words in the text they can see (and the curated variants): a synonym the thesaurus does not list, a different word form or a typo in your search finds nothing there, OpenAlex no longer returns works that only mention your words in their full text, and Europe PMC no longer returns open-access full-text matches. The fallback passes (when fewer than 15 results match every concept) and "Search exactly as typed" give some of that breadth back. Every ranking, BM25 included, works only on what the sources returned (a few hundred results at most), so a strong match that none of them ranked highly is never seen.
- **A lookup cannot read arbitrary pages.** A browser may not fetch a publisher's page and Sourcly does not scrape or use a proxy, so a link is only understood when it carries a DOI or an ID, or when OpenAlex happens to store it as a landing page; otherwise the page says it could not identify the link. A bare number is never taken for a PubMed ID, a publisher page without a DOI in its address (ScienceDirect's `pii` addresses, IEEE `document` addresses) usually fails, and a title that is only close to a known one can match the wrong work (the similarity is shown). References, citing works and related papers come only from OpenAlex.
- **Crossref and OpenAlex metadata have gaps.** Crossref has no language and few abstracts, and its search cannot require every word; OpenAlex's type, language and keyword assignments are automatic and are sometimes wrong, and it may not know a very recent work. A lookup merges what each source has, so a field one of them lacks can still be empty.
- **Reference lists (APA 7) may need manual checks.** Metadata can be incomplete: volume, issue and pages are missing for many records, author names that arrive as one piece of text are split by rule and can be wrong, titles are not put in sentence case, and editors, publishers and places are not collected. The app lists what to check under each reference, but the checking is yours.
- **In-text citations need your eye.** They follow the APA 7 rules listed above, but they have no page numbers, do not combine several sources, and depend on the author names the sources gave. A title standing in for an author is in title case, where the guides disagree. Check each against your reference list.
- **The saved list lives in one browser.** It is not synced, and clearing the site's data, using another browser or profile, or private browsing loses it. It holds a snapshot of each result, which can go out of date (a source may later correct a title or flag a retraction).
- **The search protocol shows what was asked, not what came back.** Sources change, so it cannot promise the same results later, and it holds counts, not the results themselves.
- **A ranking is a view, not a verdict.** Different weights give different, equally defensible orders. The point of Sourcly is that you can see and change why.
